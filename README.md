# ML-1 — Governed Fraud Detection System

**Status: ~70%.** The measurement machinery, the governance documentation, the
fairness analysis, the scoring API and the monitoring job all exist and run.
What is left is real data, independent validation, and containerisation.

```bash
python src/generate.py && python train.py    # analysis + docs/RESULTS.md + artifact
python -m pytest tests -q                    # 9 API and monitoring tests
uvicorn serve:app --port 8000                # scoring service
python monitor.py                            # drift report off the decision log
```

Everything in `docs/RESULTS.md` is regenerated by that command. It is not
hand-edited, and the narrative sentences in it are formatted from the measured
numbers rather than written ahead of them — including the ones that came out
against my prior (see the SMOTE/class-weight note in §3).

## What is built

- **Leakage audit with teeth** (`src/leakage.py`). Three post-decision fields are
  planted in the raw feed; a denylist excludes them *and* a univariate-AUC screen
  independently flags them, which is the layer that catches leaks nobody
  predicted. `assert_clean()` raises before every fit.
- **Imbalance bakeoff, actually run** (`src/imbalance.py`). Baseline vs class
  weights vs SMOTE — SMOTE implemented here rather than imported, so the
  interpolation semantics are inspectable. Identical model config across all
  three, evaluated out-of-time.
- **Metrics a risk reviewer asks for** (`src/metrics.py`): AUC/Gini, KS,
  precision and recall at a *fixed* FPR, Brier, reliability table, PSI with the
  standard bands stated. No accuracy, anywhere.
- **Threshold economics** (`src/threshold.py`). Operating point is the argmin of
  a $-weighted cost curve — fraud loss amount-weighted, insult cost, lost margin,
  review cost — benchmarked against a rules-only incumbent and against
  approve-everything.
- **Adverse-action reason codes** (`src/reason_codes.py`). Top-3 contributors per
  decline in plain English, in the shape of the record an agent reads out, with
  the FCRA §615(a) / ECOA Reg B framing named and the attribution method labelled
  honestly as occlusion, not SHAP.
- **Out-of-time split**, with in-sample AUC reported next to out-of-time AUC.
- **Disparate-impact analysis** (`src/fairness.py`, RESULTS.md section 8): AIR against
  the 80% rule, score-distribution comparison, AIR across five operating points,
  and a **proxy ablation** that reports what fraction of the recoverable group
  signal survives dropping the suspected proxies -- quantified, not a binary.
- **Scoring API** (`serve.py`, FastAPI): returns score, decision, reason codes,
  **model version, policy version and threshold**, and appends every decision
  with its feature vector to an audit log.
- **Monitoring job** (`monitor.py`) that runs against that decision log rather
  than a warehouse snapshot, ranking four drift signals by how fast they can
  actually page someone. Returns `insufficient_data` below 200 decisions --
  never `healthy`.
- **Validation report sections 1-10** including promotion criteria, rollback
  triggers, the monitoring plan, stability bands with owners, and a change log
  that records both versions as **unsigned**.

## The finding worth talking about

Population-level PSI is ~0.000 on every feature and on the score, while the model
still loses ground out-of-time. That is not a contradiction — it is the central
monitoring problem in fraud. The adversary changed behaviour inside a 1.2%
subpopulation, and a distribution statistic over all transactions cannot see a
shift that the legitimate mass swamps. RESULTS.md §6 shows the same PSI computed
on fraud rows only, where it moves (mcc_risk 0.116 → "monitor"), and then makes
the point that matters: that column needs labels, chargebacks arrive weeks late,
so it can never page anyone in time. The only label-free early signal is
**alert-rate drift at a frozen threshold**, which is why the ranking of the four
drift signals is in the document and why feature PSI is ranked last.

## The fairness finding

Proxy ablation is the test the spec calls the sophisticated part, and it is
worth reading the number rather than the headline. Dropping the two suspected
proxies cuts the model's ability to *reconstruct* group membership from AUC
0.727 to 0.553 — most of the signal gone — while the outcome disparity moves by
+0.005. Reconstructability and impact are different questions, and fixing the
first is not evidence of fixing the second. Reporting only the reconstruction
drop would have made a cosmetic change look like remediation.

The caveat is stated in the document too: the disparity here is small to begin
with (AIR 0.99, well above the 0.80 screen), so there is little room for ablation
to move it. The machinery is demonstrated; the scenario is benign.

## What is NOT built

1. **Independent validation.** Developer and validator are the same party. Under
   SR 11-7 this alone blocks production use, and no amount of further writing
   fixes it. Both versions in the change log are recorded as **unsigned**.
2. **Real data.** IEEE-CIS swap-in is a `load()` replacement; every number in
   this repo is a property of the generator and changes when it happens.
3. **Docker / deployment.** The API runs under uvicorn locally. No container, no
   CI, no load test, and therefore no p99 figure for the service itself.
4. **TreeSHAP** replacing occlusion attribution, and focal loss in the bakeoff
   (needs a custom objective; `HistGradientBoostingClassifier` stands in for
   LightGBM, which is not installed here).
5. **Business-necessity and less-discriminatory-alternative analysis.** The AIR,
   the threshold sweep and the ablation exist; the legal analysis around them
   does not. ML-3 implements the LDA search — this project does not.
6. **Intersectional fairness.** One binary synthetic attribute, the crudest
   possible cut, and the attribute is fabricated by this repo.
7. **Evidently** specifically. `monitor.py` covers the same ground and adds the
   label-free alert-rate signal, but the named library is not used.
8. Monotonic constraints, feature-stability-driven selection, and an automated
   champion retraining pipeline.
